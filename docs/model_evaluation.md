# 模拟数据基线模型评估（2026-09-07）

## 一句话结论

数据处理、模型训练、解释和 Agent 调用链路已经跑通，但模型在独立后段测试集上只能找出 40 个风险升级样本中的 4 个，**当前只能作为技术原型，不能宣称预测效果达标**。

## 已完成且不依赖其他成员的部分

- 接入 7 张模拟数据表，共 200 家供应商、52 周、10,400 条周快照；
- 校验主键、外键、重复值和每家供应商 52 周完整性；
- 重新计算事件数、风险分、整改状态和未来三周升级标签，全部与源数据一致；
- 构造 16 个只使用当周及历史信息的特征；
- 按时间先后切分数据：1–26 周训练、27–34 周验证、35–44 周测试；
- 对逻辑回归、随机森林、XGBoost 进行同口径比较；
- 生成数据质量、模型指标和 SHAP 全局解释文件；
- 将训练后的模型接入 Dynamic Prediction Agent，并保留人工复核门禁。

## 模型结果

验证集用于选模型和阈值，测试集只用于最后验收。根据验证集 PR-AUC，当前自动选择 XGBoost；但三种模型在后段测试集上都明显退化。

| 模型 | 验证 PR-AUC | 验证召回率 | 测试 PR-AUC | 测试召回率 |
|---|---:|---:|---:|---:|
| 逻辑回归 | 0.1394 | 70.21% | 0.0175 | 12.50% |
| 随机森林 | 0.4629 | 51.06% | 0.0412 | 10.00% |
| XGBoost | 0.5132 | 54.26% | 0.0309 | 10.00% |

XGBoost 在测试集阈值 0.95 下：命中 4 条、漏掉 36 条、误报 59 条。这个结果必须与“工程链路完成”分开表述。

## 为什么后段效果差

测试集的 40 个升级标签中，30 个来自 `SUD` 突发型样本。其风险发生前往往没有近期事件：测试集正样本的四周事件数均值为 0，距离上次事件平均 41.2 周。换句话说，系统只看到过去时，突发事件本身尚未出现，现有字段没有足够的提前信号。

这是基于数据分布作出的诊断，不代表算法代码失效。为了得到可信提升，应优先补充真正领先于风险的字段，例如 SLA 下降、延期变化、关键人员波动、舆情早期信号等；不应把供应商编号里的 `SUD` 字样作为特征，因为那相当于把案例答案直接告诉模型。

## 当前可演示范围

执行：

```powershell
python -m app.main train
python -m app.main real-data-demo
```

演示可展示“全量模拟数据 → 历史特征 → 训练模型 → Dynamic Prediction Agent → Evidence Agent → 候选建议 → 等待人工复核”的完整链路。模型文件默认不提交 Git，克隆后需在本地重新训练。

## 输出文件

- `artifacts/reports/data_quality.json`：数据质量验收；
- `artifacts/reports/model_metrics.json`：三种模型的验证及测试指标；
- `artifacts/reports/model_metadata.json`：模型、阈值、字段和时间切分说明；
- `artifacts/reports/shap_global.csv`：全局特征影响排序；
- `artifacts/reports/shap_top_features.json`：便于前端或文档读取的解释结果。
